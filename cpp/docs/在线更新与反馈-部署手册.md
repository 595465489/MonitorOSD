# MonitorOSD 在线更新 & 意见反馈 · 部署手册（宝塔面板）

对应版本：v1.3.0（C++ 单文件版）
客户端已内置：WinHTTP 请求、SHA-256 校验、HMAC-SHA256 签名、自替换升级。

---

## 一、整体流程

```
客户端                                    你的服务器（宝塔）
──────                                    ─────────────────
启动 8s 后 / 每 6h 检查  ──GET──▶  /api/latest.json      （静态文件，手工发布）
点击「立即更新」        ───GET──▶  /api/pkgs/MonitorOSD_1.3.1.exe
下载完 → SHA-256 比对 → 换名 → 重启
点击「提交反馈」        ──POST──▶ /api/feedback.php     （PHP 收单 → JSONL 落盘）
你查看/导出            ◀──GET──   /api/admin.php        （带 HTTP 认证）
```

**服务器只需要三样东西**：一个静态目录、一个 PHP 脚本、可选一个管理页。
不需要数据库、不需要 WebSocket、不需要第三方 SDK。

---

## 二、宝塔建站（5 分钟）

1. **建站点**：宝塔 → 网站 → 添加站点
   - 域名：`osd.你的域名.com`（有备案就上 HTTPS，Let's Encrypt 免费申请）
   - PHP 版本：7.4 / 8.0 / 8.1 均可
2. **建目录**：进入站点根目录，新建 `api`，再在 `api` 里建 `pkgs`
   ```
   /www/wwwroot/osd.你的域名.com/api/
   ├── latest.json        # 客户端拉取的版本清单
   ├── feedback.php       # 反馈接收
   ├── admin.php          # 反馈查看（加认证）
   ├── pkgs/              # 安装包
   │   └── MonitorOSD_1.3.1.exe
   └── feedback/          # 数据目录（PHP 自动创建，需可写）
   ```
3. **上传** `server/` 下的三个 PHP 文件到 `api/`
4. **目录权限**：宝塔 → 文件 → 选中 `api` → 权限 → 所有者 `www`，755；`feedback` 目录给 755 可写
5. **伪静态/防火墙**：
   - 宝塔防火墙放行 80/443；若开了「防跨站攻击(open_basedir)」，确保 `api/feedback` 在允许路径内
   - 关闭对该目录的 `php` 之外的执行权限（安全加固 → 防跨站文件执行）

> ⚠️ **必须改盐值**：`feedback.php` 第 20 行 `FEEDBACK_SALT`，与 `main.cpp` 里的 `kFeedbackSalt` 保持一致，
> 改成你自己的随机串。两边不一致 → 客户端永远收到 403。

## 三、发布一个版本

### 1. 客户端配置（config.json）
```json
{
  "UpdateBase": "https://osd.你的域名.com/api",
  "UpdateChannel": "latest",
  "CheckUpdateOnStart": true,
  "UpdateCheckHours": 6
}
```
`UpdateBase` 留空则用编译期默认值 `main.cpp::kDefaultUpdateBase`（发版前务必改掉）。

### 2. 打包
```bat
cd cpp
build.bat
copy MonitorOSD.exe ..\..\发布\MonitorOSD_1.3.1.exe
```
命名必须是 `MonitorOSD_<版本号>.exe`，发布脚本靠它取版本号。

### 3. 生成清单（二选一）
**A. 用脚本（推荐，自动算 sha256）**
```bash
php /www/wwwroot/osd.你的域名.com/api/publish.php \
    --dir=/www/wwwroot/osd.你的域名.com/api/pkgs \
    --url=https://osd.你的域名.com/api/pkgs \
    --channel=latest
```
若 `pkgs/MonitorOSD_1.3.1.notes.txt` 存在，会逐行读成更新说明。

**B. 手工写 latest.json**
```json
{
  "version": "1.3.1",
  "url": "https://osd.你的域名.com/api/pkgs/MonitorOSD_1.3.1.exe",
  "sha256": "用 certutil -hashfile MonitorOSD_1.3.1.exe SHA256 得到",
  "size": 606208,
  "force": false,
  "notes": ["修复华硕显示器写队列偶发失败", "新增在线更新与意见反馈"]
}
```
> `sha256` **必填**。客户端拿不到 64 位十六进制哈希会直接拒绝安装（防中间人替换）。

### 4. 客户端行为
| 场景 | 行为 |
|---|---|
| 启动 8 秒后 | 静默检查，仅写日志，不弹窗 |
| 每 `UpdateCheckHours` 小时 | 静默检查（0 = 关闭） |
| 系统管理页 → 检查更新 | 打开窗口并自动检查，可见进度/说明 |
| 有新版本 | 显示「立即更新」→ 下载 → SHA-256 校验 → 「重启并完成更新」 |
| 校验失败 | 删除下载文件，明确报错，不动现有程序 |
| 换名失败（目录只读/权限） | 程序内提示，原版本回滚保留 |

**升级实现细节**：`当前 exe → .old` → 新文件就位 → 起新进程 → 旧进程退出 → 下次启动删 `.old`。
中途任何一步失败都会回滚到原 exe，不会出现「升级后没程序」。

## 四、反馈链路

### 客户端采集内容
| 字段 | 说明 |
|---|---|
| `type` | 问题反馈 / 功能建议 / 其他 |
| `text` | 用户填写的正文（限 4000 字） |
| `extra` | 可选补充（粘贴报错文本） |
| `with_log` | 是否附带诊断信息（默认勾选） |
| `monitors` | 显示器型号 / EDID 型号 / 序列号 / DDC 状态 |
| `log` | `log.txt` 最近 120 行（≤8KB） |
| `machine` | 机器码 **SHA-256 前 16 位**（不上报原始 GUID） |
| `user` / `os` | 当前 Windows 用户名 / 版本号 |
| `hash` | `base64(HMAC-SHA256(body, salt))` |

### 服务端核对
```php
$payload = substr($raw, 0, strrpos($raw, ',"hash"')) . '}';
hash_equals(base64_encode(hash_hmac('sha256', $payload, SALT, true)), $hash);
```

### 查看反馈
浏览器打开 `https://osd.你的域名.com/api/admin.php`，支持按类型/版本筛选、关键字搜索、导出 CSV。
**务必加访问限制**：宝塔 → 网站 → 设置 → 访问限制 → 启用「密码访问」。

## 五、命令行（现场运维 / 自检）

```bat
MonitorOSD.exe /selftest                 :: 10 项自检：SHA-256 / HMAC / 版本比较 / 清单解析 / HTTP GET+POST
MonitorOSD.exe /checkupdate              :: 检查更新（输出到控制台 + log.txt）
MonitorOSD.exe /feedback "描述" 1 --log  :: 直接提交反馈（1=功能建议，--log 附带日志）
```
`/selftest` 在部署完成后跑一遍，10 项全 OK 说明链路通了。

## 六、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 客户端报 `网络连接失败(12029)` 或超时 | 域名不通/证书错/防火墙 | 服务器本机 `curl -I https://域名/api/latest.json` |
| 返回 403 | 两边盐值不一致 | 核对 `FEEDBACK_SALT` 与 `kFeedbackSalt` |
| 返回 404 | `latest.json` 路径不对或通道名不匹配 | 检查 `UpdateChannel` 与文件名 |
| 下载后提示「校验失败」 | CDN 缓存旧文件 / 手工改过 exe | 清缓存，重新 `publish.php` 生成清单 |
| 提示「清单缺少 sha256」 | 手写清单漏了哈希 | 用 `publish.php`，或 `certutil` 补上 |
| 升级后程序打不开 | 目录权限不足导致换名半途失败 | 已自动回滚；改目录权限或以管理员运行 |
| 网吧有代理 | 走了代理导致内网地址不通 | 设 `no_proxy` 环境变量，客户端已支持读取 |
| 反馈显示「提交失败(500)」 | `feedback` 目录不可写 | `chown -R www:www api/feedback` |

## 七、安全边界（实话实说）

- **盐值写在 exe 里，能被逆向提取**。它只用来过滤脚本扫接口，不是可信认证。真正的防护是：单 IP 限流（20 条/小时）+ 字段白名单 + 长度截断 + 不执行任何用户输入。
- **反馈内容一律当纯文本**。`admin.php` 全部 `htmlspecialchars` 输出，落盘是 JSONL，不存在 XSS/命令注入面。
- **升级包只认 SHA-256**，清单走 HTTPS。如果域名被劫持，攻击者仍可改清单——要更强就上代码签名证书（`signtool`），客户端校验前先验签，这是下一步可选项。
- **不上报隐私**：机器码哈希化、日志截断、不采集硬件全量信息。

## 八、后续可选项（按需再做）

1. **代码签名**：买 OV 证书后 `signtool sign`，同时消掉 SmartScreen 警告
2. **灰度通道**：`UpdateChannel: "beta"` + 服务器多一份 `beta.json`，只给测试机放开
3. **强制更新**：清单里 `force: true`（客户端已解析，目前是提示语义，可改成阻断使用）
4. **反馈转邮件/企业微信**：`feedback.php` 末尾加 `mail()` 或企业微信机器人 webhook，新反馈即时提醒
5. **安装包瘦身**：目前 `/MT` 静态链接约 590KB，可接受；若要更小可改 `/MD` + 附带 VC 运行库
