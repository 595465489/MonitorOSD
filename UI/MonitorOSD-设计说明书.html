01项目概述

MonitorOSD 是一款 C# WinForms 单文件应用（约 70 KB，免安装直接运行），通过 DDC/CI（dxva2.dll）直接控制显示器硬件参数，不依赖厂商驱动与 OSD 菜单。

维度说明
核心场景顾客把显示器参数调乱 → 网管一键还原到「基准」配置，全程 < 2 秒
使用环境网吧 / 电竞馆前厅或机房，环境光偏暗，操作者非专业用户
目标机型卓威 ZOWIE XL2566K / XL2746K、华硕 ROG·TUF、AOC / 爱攻 等电竞屏
技术栈C# WinForms · GDI+ 自绘 · 单文件发布 · 目标 Windows 10/11

界面只有两个页面，用顶部页签切换：参数设置（日常调节）与系统管理（还原策略、维护、软件设置）。不做多级菜单、不做向导式流程——网管需要在 3 秒内找到「一键还原基准」。

02设计原则

① 状态一眼可辨。当前选中的显示器、当前激活页签、DDC/CI 连接状态，各自固定在唯一位置，靠颜色与发光表达，不靠文字提示。
② 主操作唯一且醒目。整屏只有一个高饱和强调色实心按钮——「一键还原基准」。其余操作为中性色，绝不与它抢视觉。
③ 品牌自适应。强调色跟随显示器品牌（见第 10 节），同一套版式承载 ZOWIE 的红、外星人的银白、泰坦军团的蓝。
④ 深色为主，红仅作点缀。底色近黑，红色以「大范围浅渐变 + 局部实心」两种浓度出现：背景渐变负责氛围，前景实心负责指引。
⑤ 置灰不隐藏。硬件不支持或依赖关系未满足的参数保留在原位，降色并附一句原因文案，杜绝「找不到」。

为什么要 1440×960 这个「不太标准」的尺寸？网管机普遍是 1920×1080 单屏或双屏，960 高留出任务栏与若干余量，窗口居中后上下对称；同时 1440 宽刚好放下 7 列参数控件而无需横向滚动。窗口需支持自由缩放，缩放时左栏定宽、右栏拉伸（滑条长度随之变化），最小宽度建议 1180。

WinForms 等价实现（以 #F04438 为例）
// 135° = 右上 → 左下；GDI+ 角度以 X 轴为 0、顺时针为正
var b = new LinearGradientBrush(rect, Color.FromArgb(128, 255, 240, 38), Color.Transparent, 135f);
var cb = new ColorBlend(3);
cb.Colors     = new[]{ Color.FromArgb(128,255,240,38),
                       Color.FromArgb( 18,255,240,38),
                       Color.FromArgb(  0,255,240,38) };

b.InterpolationColors = cb;
「大范围但少红像素」是怎么做到的？起点 alpha 高达 0.5，但衰减极快——过半画面已降到 0.07，左下角完全归零。视觉上是「一整片斜向的红雾铺满窗口」，但因为大部分区域 alpha 极低，整体红色像素占比很小，不会压过前景内容。

4.6 光晕衍生算法（换肤核心）

换主题色时，背景渐变与卡片外发光不使用纯强调色，而使用派生的「光晕色」，否则金 / 青 / 紫等高亮度色铺满后会产生廉价 RGB 灯效感。

// 强调色 → 光晕色
HSV hsv = RgbToHsv(accentColor);
hsv.S *= 0.5f;      // 饱和度 × 0.5
hsv.V *= 0.35f;     // 明度   × 0.35
Color glow = HsvToRgb(hsv);
强调色派生光晕色验证结果
#F04438（红）#6E2A24已成稿，勾选态、品牌默认
#F5B913（金）#6E5510全幅渐变下依然协调
#22D3EE（青）#0E4A52全幅渐变下依然协调
#4C8DFF（泰坦蓝）#24477E冷色铺满不发灰
#C9D4DD（外星人银白）#565C63高明度低饱和，需靠 alpha 提亮
光晕色本身很暗，所以 光晕/渐变的起始 alpha 可放宽到 0.5 – 0.7，不必沿用前景色的 alpha 值。

选中态（默认选中第一张 = 主显示器）

选中通过两处信号叠加表达，不只靠发光：

  1. 刷新率文字用强调色（主卡 360 Hz 为红；未选中的副卡 144 Hz 为中性 #FAFAFA）。
  2. 边缘发光——同时施加内发光与外发光：
effects: [
  { type: "INNER_SHADOW", color: accent a0.70, radius: 3,  spread: 0 },
  { type: "INNER_SHADOW", color: accent a0.30, radius: 8,  spread: 0 },
  { type: "DROP_SHADOW",  color: accent a0.35, radius: 20, spread: 0,
    offset: {x:0,y:0}, showShadowBehindNode: true }
]

三个 shadow 叠加的效果：贴边一圈锐利亮线（r3）+ 一圈柔和内晕（r8）+ 卡外弥散光（r20）。未选中的卡 effects: []，无任何发光。

GDI+ 落地提示：外发光无法直接画，需要用 GraphicsPath 生成圆角矩形路径，再叠 3–4 次 DrawPath，每次 Pen 更粗、alpha 更低（例如 r=16/12/8/4，alpha=0.06/0.09/0.14/0.22），模拟弥散；内发光则用 PathGradientBrush 的 CenterColor = Transparent + SurroundColors = accent 填充路径内圈。

8.12 置灰参数行

规则：标签色由 #E4E4E7 降到 #71717A，控件不渲染，紧接一句 12px #71717A 的原因说明。示例：「用户色温 RGB」→「色温须为「用户」后可调」；页面底部还有一条整宽说明：「FreeSync 自适应同步 — 走显卡驱动，请用显示器 OSD 或显卡面板调整」。

硬性要求：任何不可调的参数禁止直接消失。位置保留 + 原因文案，是网管定位问题的唯一线索。

// 数据模型建议
enum AccentMode { Auto, Manual }          // config.accentMode

static readonly Dictionary<string, (string Accent,string Glow)> BrandAccent = new()
{
    // EDID 厂商 ID → 品牌色
    ["BNQ"] = ("#F04438","#6E2A24"),   // BenQ / ZOWIE
    ["ASU"] = ("#F04438","#6E2A24"),   // ASUS
    ["HKC"] = ("#F04438","#6E2A24"),
    ["AOC"] = ("#FF5A47","#7A2F28"),
    ["DEL"] = ("#3B82F6","#22416E"),   // Dell
    ["HWP"] = ("#38BDF8","#1A5570"),   // HP
    ["HEC"] = ("#E8483C","#6E2A26"),   // HUAWEI
    // …其余见上表
};

Color ResolveAccent(string edidVendorId) =>
    config.accentMode == AccentMode.Manual ? config.manualAccent
    : BrandAccent.TryGetValue(edidVendorId, out var b) ? Parse(b.Accent)
    : AccentDefault;   // #F04438
光晕色不单独存储。上表的 glow 值只是预制校验结果；运行时一律由 ResolveAccent() 的返回值经第 4.6 节算法实时派生，保证新增品牌无需手填两个颜色。

12落地建议（WinForms）

设计要素实现要点
窗口FormBorderStyle=None + 自绘标题栏；SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)；圆角用 CreateRoundRectRgn 或 DwmSetWindowAttribute
双缓冲根容器 SetStyle(AllPaintingInWmPaint | UserPaint | OptimizedDoubleBuffer, true)，全部绘制走 OnPaint
圆角矩形GraphicsPath + 4×AddArc，配合 SmoothingMode.AntiAlias
背景渐变见 4.5 代码，注意 GDI+ 角度以 X 轴为起点顺时针，45° 视觉方向对应 135f
卡片外发光GraphicsPath + 多次 DrawPath（由粗到细、由淡到浓），或离屏 Bitmap 做高斯模糊后 DrawImage
卡片内发光PathGradientBrush：CenterColor = Color.Transparent，SurroundColors = accent，填充路径
滑条 / 分段 / 复选全部自绘 UserControl；不要用系统 TrackBar / CheckBox（无法改样式且 DPI 表现不一致）
字体子集化内嵌，或降级为「微软雅黑 UI + Consolas」。等宽数值列必须用等宽字体，否则滑条数值会左右抖动
换肤把 accent / glow / onAccent 三个值收进一个 Theme 静态类，所有绘制读取它；换色后 Invalidate() 整窗重绘
性能渐变与发光缓存到 Bitmap，仅在尺寸变化或换肤时重绘；避免每帧构建 GraphicsPath
